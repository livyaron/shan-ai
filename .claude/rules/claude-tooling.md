# Claude Code tooling in this repo: skills, ECC, secret guard

<!-- Moved verbatim from the root CLAUDE.md on 2026-10-26. Loads only when Claude touches a matching file. -->

- **find-skills (vercel-labs/skills):** installed project-scoped at `.claude/skills/find-skills/` (pinned in `skills-lock.json`). When a task falls outside what the installed skills and these rules cover, check for an installable one (`npx skills find <query>`) — user decision 2026-10-26, replacing "before every task". Install new skills **project-scoped** (`npx skills add <owner/repo> --skill <name> --agent claude-code -y`), never `-g`: cloud sessions are ephemeral and a global install dies with the container. Read every SKILL.md before committing it — skills run with full agent permissions and the repo is public.
- **ECC (everything-claude-code) — a hand-picked subset (user 2026-10-26: "a + secrets").** Source = the ORIGINAL `affaan-m/everything-claude-code` only (its README warns re-uploads such as `WorldFlowAI/everything-claude-code` — a one-commit January snapshot — may carry malware). Installed project-scoped, copied unmodified: 13 agents in `.claude/agents/` (planner/architect, code/python/fastapi/database/security/typescript/react reviewers, silent-failure-hunter, build-error-resolver, tdd-guide, pr-test-analyzer) and 11 skills in `.claude/skills/` (fastapi/python/postgres/react patterns, python/react testing, database-migrations, error-handling, api-design, verification-loop, regex-vs-llm-structured-text). `.claude/ecc-lock.json` pins version + commit + sha256 of every file — an update is a re-read + re-pin, never a blind copy. **Deliberately NOT installed:** ECC's `rules/` (always-loaded, and they contradict this file: "never mutate", files <800 lines, 80% coverage + mandatory E2E/integration tests against a DB, conventional commits that drop the attribution trailer), its commands (collide with built-in `/code-review`, `/plan`), and all ~27 of its hooks (tmux/dev-server blockers, Prettier rewriting whole files, fail-closed MCP/GateGuard blocks, memory hooks that die with a cloud container). **CLAUDE.md and `.claude/rules/` win over anything an ECC agent or skill says** — e.g. tests stay synthetic-frame, no local DB, minimal diffs.
- **Secret guard (`.claude/hooks/secret_guard.py`, wired in `.claude/settings.json`):** PreToolUse on Bash + the GitHub MCP file-writing tools. Blocks `git commit` / `git push` / MCP pushes whose ADDED lines carry a provider key (Google, Telegram, Groq, Anthropic, OpenAI, Resend, GitHub, AWS), a private key, a Postgres URL with a real password (any password on a Railway/Supabase/AWS host), a `NAME=value` for this project's secret names, or a `.env` file. Never echoes the secret (first 4 chars only). False positive → `secret-guard: allow` on that line. Fails OPEN on its own errors. Known hits: `docs/superpowers/plans/` once held the old `postgres` service's DB password — scrubbed to `$RAILWAY_DATABASE_URL`, but the password is still in git history; `tests/test_key_redaction.py` holds two fake keys. Railway service `old-db-archive` only keeps the volume holding `/archive/old-postgres-20261026-165955.dump` (sha256 `16adea0a…7798`) — never redeploy it; its source DB is gone. Tests: `tests/test_secret_guard.py` (every fake secret is built at runtime — a literal one would be blocked by the guard itself).
