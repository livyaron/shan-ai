# Lessons module (schema `lessons`)

<!-- Moved verbatim from the root CLAUDE.md on 2026-10-26. Loads only when Claude touches a matching file. -->

- **מערכת לקחים (schema `lessons`, PLAN-lessons-module.md):** lives ONLY in schema `lessons` — `app/services/lessons_schema.py` is its DDL (startup, idempotent, never raises) and must never issue DDL against `public` beyond the two `REFERENCES public.users(id)` links (a test greps for it). PostgREST runs as `lessons_anon`, granted schema `lessons` only; `GET /lessons/api/_status` reports the live isolation check (`leaks` must be `[]`). Every write passes `lessons_access.check_request` (actor = caller's profile or own referent group; module admin acts for anyone). Module lessons and `lessons_learned` stay separate. Never create Shan-AI users, never auto-link people/projects by name. **This module goes through a PR, and the PR is merged automatically once CI is green** (user instruction 2026-10-16: "merge אוטומטי, תמיד" — replaces the old "no merge without the owner" rule; the standing merge + deploy-verify rules apply). The UI (`lessons_ui/`) is built in the Docker stage `ui` and served by `app/routers/lessons_spa.py` at `/lessons/` — never commit `dist/`; identity comes only from `/lessons/api/me` (no passwords in the module). Runbook: `docs/lessons-module.md`. **People (2026-10-17):** ניהול משתמשים (`/lessons/api/_people`) lists EVERY Shan-AI user and sets their module role/projects/referent groups before their first visit (a new PM has no old-system profile to link); `lessons_admin.person_problems`/`group_problems` are the ONLY definition of "not set up". The links tab is migration-only: it stays, marked done, at the menu's end once `migration_left` = 0. **Phone app (PLAN-lessons-mobile.md):** `/lessons/login` is the module's own login (an installed PWA never leaves `/lessons/` to sign in) and the only app route open without a session (besides `index.html` itself: the service worker precaches it with no session, and gating it once cached the /login page as the app shell — the Android login loop of 2026-10-16); `LESSONS_REMEMBER_DAYS` (default 7 = off) is raised only after information-security approval — it is the Shan-AI cookie.
- **קישור פרויקטים ללקחים (PLAN-lessons-projects.md):** `app/services/lessons_project_link.py` is the ONLY place a master-file project becomes a lessons project — `STAGE_MAP` (file stage → lessons stage indexes), `TYPE_MAP`, `RISK_BY_LEVEL` (the pattern engine's handling level, never the model) and the manager chain (confirmed `manager_aliases` → user → lessons profile; **never a name match**; unresolved = `pm_unassigned` "טרם שויך", a no-login profile in `NO_LOGIN_NAMES`). Source = ACTIVE `public.projects` only (inactive rows are phantoms of the old all-sheets sync). Admin tab "קישור פרויקטים" (`/lessons/api/_project_links`): suggestions are hints only; "create the missing" is refused while any lessons project is undecided; a project is never created on an unknown stage. The file owns name/manager/stage/type/risk; the module owns station type/site/equipment (`station_type_set`). The Lovable re-import refuses to write while a module-only project exists (`local_only_projects`). **Every live upload** runs `sync_after_upload()` (both upload paths; own transaction; never fails the upload): `sync_plan` (pure) applies the file's fields to linked projects, fills a manager through the confirmed chain ONLY on a project held by the `pm_unassigned` placeholder — a real manager who differs from the file is never replaced without the admin (user decision 2026-10-19; it waits as `manager_differs`), marks projects gone from the file `shan_active=false` (never deleted), and creates new file projects — except one that `possible_duplicates` says may BE an undecided lessons project (it waits for that decision; one undecided project no longer holds back all creation, user 2026-10-19) — only once the engine answered (`_levels` → None = engine down: no risk is written, nothing is created — an empty answer once reset every risk to "low"). **ניידות is not a lessons project (user 2026-10-19):** `EXCLUDED_TYPES` — never created, never offered for linking, not a completable type; `remove_excluded` (every sync) deletes the ones already in the module ONLY when they hold no lessons and no distributions, keeps and reports the rest. **"מחק" in פרויקטים להשלמת נתונים (2026-10-19):** `dismiss` takes ONE file project out of the module (`master_overrides.excluded`; `_masters` drops it everywhere — creation, suggestions, completion), only when no lessons project is linked to it; reversible ("טופלו" → "הוצאו מהפקת לקחים" → החזר); the master file is never touched. **No unfounded defaults (2026-10-19):** a stage or project type the file does not give holds the project (`missing_fields`) until an admin completes it (`complete` → `lessons.master_overrides`, server-only; a value the file gives always wins). **Work list:** `lessons_project_link.link_issues` is the ONLY definition of "ממתין לטיפול" (undecided / manager_differs / manager_unresolved / manager_placeholder / sync_error) — the tab shows only those by default, "טופלו" for control; station type / site / equipment never keep a project there. Each project syncs in its own savepoint (`shan_sync_error`), one activity-log line per change, the run's five-category report in `lessons.sync_runs` (server-only). Excel completion: `lessons_link_sheet.py` (pure) — `GET/POST /lessons/api/_project_links/completion(.xlsx)`, preview before apply, empty cell = no change, stale "current value" refused, users read by `#id` only. DB trigger `lessons.lock_master_fields` refuses UI edits (role `lessons_anon` only) of name/stages/type/risk/link on a linked project — never make it SECURITY DEFINER (current_user must stay the caller). "חסר נתונים" (station type not chosen / no site — equipment is optional, user decision 2026-10-19) is defined ONLY in `lessons_ui/src/lib/projectProblems.ts` — the PM's cards and the admin "השלמת נתונים" tab both read it; saving a station type writes `station_type_set=true`. The UI's project writes throw on a server refusal and never show a change the server did not keep.
- **דשבורד הלקחים — ניתוח AI שמור ו"ממתינים לאישור" (2026-10-17):** `summarize-lessons` saves every COMPLETE answer (`lessons_ai.summary_complete` — reached its `ציון ביטחון` line) in `lessons.ai_summary_cache`, keyed by `lessons_ai.prompt_key` = sha256 of the exact prompt (data + role + prefs + insights; project lists sorted by name so heap order is not "new data"). Same prompt → the saved answer, no model call; `cacheOnly: true` (sent when the page opens or the filters change) never reaches the model and is not rate-limited — 204 when nothing is saved. The table is server-only like `referent_members` (not in `TABLES`, `REVOKE ALL` from `lessons_anon`). An answer shown as saved hides the button ("הניתוח מעודכן לנתונים"); it reopens by itself when the data changes. "ממתינים לאישור" (card, banner, KPI tab) = `lessonActions.awaitsAdminApproval` (status `new` OR `ממתין לאישור מנהל מערכת`) — the same lessons `pendingTasks` gives the admin, so the card can never disagree with the sidebar badge (a test holds them equal).
- **לקחים בדף פרויקט (2026-10-17):** `app/services/project_lessons.py` is the ONLY reader — read-only over schema `lessons`, bridged ONLY by the admin's link (`lessons.projects.shan_project_identifier`), never a name. Two lists: written on the project, and distributed to it (`lesson_implementations` + the project's answer). Another user's draft is never shown. Best-effort in a savepoint: failure → `{"ok": False}`, the page still renders. Access = the project page's own gate.
