# Pattern engine, access, taxonomy, project page, AI analysis

<!-- Moved verbatim from the root CLAUDE.md on 2026-10-26. Loads only when Claude touches a matching file. -->

- **מנוע דפוסים (PLAN.md P2):** `app/services/pattern_service.py` — **no LLM computes a number**; every metric is `{value, n, confidence, caveat}` and the thresholds live as named constants at the top of the module, nowhere else. `load_frames` is its only DB access; `compute_patterns` is pure and tested on synthetic frames. `app/services/stage_sectors.py` is the ONLY stage → sector map — never re-spell a stage or sector key; `עבודה אזרחית והרכבות` belongs to two sectors, so sector totals are never summed into a division total. Report-date clustering is measured from a cluster's first date, never chained. Page `GET /dashboard/projects/insights` ("🧠 דפוסים וסיכונים"); raw JSON `GET /dashboard/projects/patterns` stays admin-only.
- **מי רואה מה בדפוסים (PLAN.md P3):** `app/services/insight_access.py` is the ONLY place that decides it — `scope_for` reads the role (admin / `users.sector` / confirmed `manager_aliases`), `view_for` is pure and filters the engine output; the template only draws `view`. Admin: everything. `pm_dept`: all projects + league. Sector manager: projects whose current stage is in the sector + that sector's row and attribution. PM: own projects + the named league (D3). Leading indicators, risk topics, update waves, data health and the lists are admin-only (PLAN.md §8.3–8.4). `users.sector` is ALTERed at startup; `manager_aliases` auto-creates. Links are set only by an admin at `/dashboard/projects/insights/access` — **never auto-link a name**: a wrong link shows a PM someone else's projects. `stage_sectors.ASSIGNABLE_SECTORS` (no `unknown`) is what a user can be given. **View as:** an admin previews any viewer with `?as_user=<id>` / `?as_sector=<key>` / `?as_manager=<name in the file>` (`insight_access.preview_scope`) — the preview never carries admin power, and the params are ignored for non-admins (tested). **Drill-down:** every number on the page links to `?drill=<kind>&dv=<value>&dm=<metric>` (`&ds=<stage>` narrows a project drill to one stage — the league's stage mix; every label, stage and manager cell drills too); `insight_access.drill_for` returns the rows behind it and only ever filters what `view` already allows — a drill can never widen access (tested: each drill's row count equals its number). Slip/baseline moves are kept as `events` in the engine output for this.
- **טקסונומיית נושאים (v2) ודיווח "זהה":** `RISK_CATEGORIES` anchors ambiguous stems on Hebrew word edges (`_B`/`_E`) — v1's raw substrings read "הרכבת" (assembly) as a train (~230 false "outside party" hits, which manufactured the only leading-indicator signal), "מוקדם" as a control centre, "הגורמים"/"כרמיאל" as רמ"י, "לעלות"/"בעלות" as cost. **Before adding a stem, list what it actually matches in the weekly texts** (a test holds the known traps). A weekly report counts as a repeat by `near_same` (≥95 similarity, punctuation ignored), never by exact hash — a one-letter typo fix is not a new report. Weeks in stage carry `weeks_lower_bound` when history starts in that stage; show them as "לפחות". `קרקע` alone is NOT land ("עלייה לקרקע" = contractor on site, "תת קרקעי" = cable, "זיהום/יועץ קרקע" = soil) — only land-rights phrases count. **Move events** are measured against the last DATED report (`undated_between`), so a target written as text for a few weeks never swallows the move across the gap; a wave still counts consecutive pairs only, and its drill filters on both `from` and `to`. `חסם לטיפול <who>` in the file's לטיפול column is a flag (סמנכ"ל = high). **Drift** (`forecast_moved_months`, `forecast_drift`) runs from each project's OWN first dated report to its last (`_own_drift`, needs ≥2 dated reports) — never from the division's first report, which read as "never moved" for any project whose first report had no date. `ציוד/אספקה` counts supply only — the equipment nouns (שנאי/ציוד/מפסק) matched 1,599 of 1,898 entries; bare `נתי` is a person. `נגה` (the system operator) IS an outside party — user decision 2026-09-26; every hit in the reports is the company. `FROZEN` (latest weekly report or risk column says הוקפא / בהקפאה / לבטל את הפרויקט / בחינת נחיצות) is a high flag — a cancelled OUTAGE ("בוטל עקב") is not. The risk-column history never prints "לטיפול: חסם לטיפול". A target cell starting `חושמל` is energized, not undated (`ENERGIZED`). **Stage vs. report** (`stage_contradiction`, ladder `stage_sectors.STAGE_RANK`): a milestone the LATEST weekly report says already happened beyond the file's stage is a WARNING only (≥2 stages = medium, 1 = info) — never change the stage from free text (user decision 2026-09-26: a wrong guess moves a project to another sector silently). A developer's contractor ("ע\"י היזם") is not ours; a future phrase ("צפי", "טרם"…) cancels a match. Measured before shipping: 10 hits on 185 projects, all confirmed.
- **דף פרויקט:** `GET /dashboard/projects/p/<identifier>` — `pattern_service.project_history` (pure) builds status, report timeline, weekly reports (newest first, repeats marked), move events, topic evidence quotes and the risk read-out. Every risk line is a rule over that data (no LLM). Visible only if the project is in the viewer's `view` (admin / pm_dept: every project, including inactive). Two interactive charts, data from `project_chart.delay_story` / `risk_matrix` / `risk_column_changes` (pure), drawn by `templates/_project_charts.js` (inlined): **delay over time** in months on ONE axis (cumulative forecast slip, baseline slip, gap vs plan — never dates and months on the same chart), crosshair snapping to the nearest report with one tooltip for all series plus stage, moves, targets, topics, risk-column change and the week's report; **risks over time** as a topic × week matrix with the exact quote on hover. Data goes into the DOM with `textContent` only (a test checks `innerHTML` never appears). Colours: reference palette dark slots 1–3 (#3987e5 / #d95926 / #199e70), validated against #0f1826 with `validate_palette.js` (the dataviz skill's validator — not a file in this repo). Every chart has a table twin.
- **ניתוח AI מעמיק בדפוסים (PLAN.md P5):** 3 רמות זום (אגף / מגזר / פרויקט) × 4 דרגות טיפול לפי בעלים (🔴 הסלמה סמנכ"ל · 🟠 מנהל אגף השבוע · 🟡 מגזר/מנה"פ מעקב · 🟢 לידיעה). **הדרגה היא כלל, לעולם לא המודל** — `app/services/insight_triage.py` (ספים כקבועים; אושרו ע"י המשתמש 2026-09-28); הדגלים שהכללים קוראים (`frozen`, `escalation`, `stage_gap`) מחושבים פעם אחת בשורות המנוע (`pattern_service._rule_flags`). `app/services/insight_ai.py` כותב רק את המלל, ו-`validate` רץ על כל תשובה: מספר שלא בהקשר → `[?]`, ציטוט שלא נמצא מילה במילה → נמחק, מזהה פרויקט זר → נמחק. שמות מנה"פ יוצאים למודל כ-`מנה״פ #n` ומוחזרים רק בהצגה (`restore_names`) — שמות שמופיעים בתוך מלל הדיווחים עצמם כן יוצאים. מי קורא איזו רמה: `insight_access.ai_kinds_for` בלבד (רמה 3 = מי שרשאי לדף הפרויקט). טבלת `pattern_ai_analyses` (kind, as_of) נוצרת לבד; רמות 1–2 נוצרות אחרי סנכרון חי (לא ב-history replay) ובכניסה לדף כשחסר — `claim_autostart` מגביל לפעם ב-30 דק׳ לתאריך דוח, כדי שמודל שנכשל על מכסה לא יישאל בכל צפייה. usage: `pattern_analysis`.
- **תאריכים במסכי הדפוסים = DD/MM/YYYY (הוראת משתמש 2026-10-07):** המנוע שומר ISO (ממיין, משווה, JSON); רק מה שאדם קורא מומר, דרך `app/services/il_format.py` — `il_date` (ערך), `il_dates` (כל תאריך ISO בתוך מלל: caveats, סיבות, טקסט AI), `il_datetime` (UTC נאיבי → שעון ישראל). רשום על `templates.env` של `routers/projects.py`; בטסטים `il_format.template_env()`. **לא** finalize גלובלי: קישורי דריל (`dv=`) ונתוני הגרפים (`tojson`) חייבים להישאר ISO — טסט בודק שאין ISO בטקסט הנראה ושהנתונים של הגרף נשארו ISO. "נכון לדוח" = תאריך הדוח (שם הקובץ, אחרת עמודת `פירוט שבועי` האחרונה) — **לא** יום ההעלאה; לידו מוצג מתי נטען קובץ המאסטר האחרון, כדי שקובץ חדש עם אותה עמודה אחרונה לא ייראה "ישן".
